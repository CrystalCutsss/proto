# Architecture Decision Records

Каждое существенное решение оформляется отдельным файлом `NNNN-короткое-имя.md`. В нём четыре раздела: контекст, варианты, решение и последствия. ADR не переписываются задним числом. Если решение меняется, создаётся новый ADR со статусом «Заменяет NNNN», а у старого статус меняется на «Заменён NNNN».

- Фаза 1: 0004 стек, 0005 хостинг, 0006 политика сторонних skills.

## Шаблон

```markdown
# NNNN. Заголовок решения

- Статус: Предложено | Принято | Заменён NNNN | Отклонено
- Дата: YYYY-MM-DD
- Фаза: N

## Контекст
Какая проблема или ограничение. Факты со ссылками на первоисточники.

## Варианты
1. Вариант A — плюсы, минусы.
2. Вариант B — плюсы, минусы.

## Решение
Что выбрали и почему.

## Последствия
Что становится проще или сложнее; что нужно сделать; когда пересмотреть.
```
