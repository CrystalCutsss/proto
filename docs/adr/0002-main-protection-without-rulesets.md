# 0002. Защита main без branch protection

- Статус: Принято
- Дата: 2026-10-13
- Фаза: 0

## Контекст
- Репозиторий приватный, у владельца бесплатный план GitHub.
- `GET /repos/CrystalCutsss/proto/branches/main/protection` и `GET …/rulesets` возвращают **403 «Upgrade to GitHub Pro or make this repository public»**. Branch protection и rulesets недоступны.
- GitHub-прокси облачной сессии отклоняет удаление веток и push тегов, но [не ограничивает, какие ветки обновляются](https://code.claude.com/docs/en/cloud-environments#github-proxy).
- Требование: в `main` изменения попадают только через PR, который смержил владелец.

## Варианты
1. **GitHub Pro ($4/мес).**
   - Плюсы: ruleset «только PR + обязательный CI + запрет force-push/удаления» защищает от всех: людей, Claude, других инструментов.
   - Минусы: платно.
2. **Сделать репозиторий публичным.**
   - Плюсы: защита бесплатная.
   - Минусы: код, материалы ДС и прототипы видны всем.
3. **Хуки + deny-права + CI + детектирование.**
   - Плюсы: бесплатно.
   - Минусы: защищает только от действий Claude. Люди и сторонние инструменты технически могут пушить в `main`.

## Решение
Вариант 3 (выбор владельца), в несколько слоёв:
1. **Фаза 0:** временные deny-правила в `.claude/settings.json`:
   - `git push … main`, `HEAD:main`, `refs/heads/main`;
   - force push: `--force*`, `-f`, `+refspec`;
   - `git push --delete` и `-d`.
2. **Фаза 4:** PreToolUse(Bash)-хук на Node разбирает команду целиком. Он ловит:
   - push в `main` в любой форме (`git -C`, `git -c`, `git push` без аргументов на ветке `main`, `sh -c`);
   - force push;
   - удаление веток и тегов.
3. **Фаза 5:**
   - CI на каждый PR;
   - workflow `main-guard`: на каждый push в `main` проверяет через `GET /repos/{o}/{r}/commits/{sha}/pulls`, что коммит пришёл из смерженного PR. Если нет — создаёт issue с меткой `main-guard`.

## Последствия
- Bash-правила сопоставляются с текстом команды и не являются полной границей ([permissions](https://code.claude.com/docs/en/permissions)). Поэтому в Фазе 4 нужен хук, а не только правила.
- CI не блокирует мерж: это будет только сигнал. Владелец мержит PR с зелёным CI.
- Пересмотреть при переходе на GitHub Pro или Team: тогда включить ruleset, а хуки оставить вторым слоем.
